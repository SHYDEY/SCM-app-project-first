# SCM 수급·발주 관리 시스템 PRD

문서 버전: v0.1  
작성 기준일: 2026-08-13  
대상 버전: 로컬 MVP  
최종 배포 방향: Vercel + Supabase

## 1. 문서 목적

본 문서는 월간 기기·PRT·옵션 발주 업무를 웹 시스템으로 구현하기 위한 제품 요구사항을 정의한다.

초기 버전은 로그인 없이 한 명의 담당자가 전체 프로세스를 수행하는 단일 사용자용으로 구현한다. 다만 데이터 모델과 기능 경계는 향후 Supabase 기반의 팀 협업, 권한, 승인, 변경 이력 기능으로 확장할 수 있도록 설계한다.

## 2. 제품 목표

### 2.1 핵심 목표

- Excel 중심의 수요·재고·기준정보 입력 업무를 웹에서 통합한다.
- OL, SFDC, Bulk-deal, 과거 Trend, 수급회의 결과를 한 화면에서 비교한다.
- 기기와 옵션 발주량을 동일한 데이터 구조에서 계산한다.
- MOQ, Lead Time, Flexibility Rule, BOM, 장착율, Common품, 필수 옵션을 계산·검증한다.
- 발주 수량·금액·예외·조정 이력을 남긴다.
- 사장 보고 자료와 System 업로드용 Excel을 생성한다.
- 샘플 데이터가 없어도 가상데이터로 전체 화면과 업무 흐름을 시험할 수 있게 한다.

### 2.2 초기 버전에서 달성하지 않는 목표

- 실제 발주를 자동 실행하지 않는다.
- ERP, SFDC, FX-LIVE와 실시간 연동하지 않는다.
- 로그인, 다중 사용자, 역할별 권한을 구현하지 않는다.
- 입고·통관·PO Match·지불 업무를 1차 핵심 흐름에 포함하지 않는다.
- AI가 수요나 발주량을 임의로 결정하지 않는다.

## 3. 사용자 및 사용 시나리오

### 3.1 사용자

| 사용자 | 초기 버전 역할 |
|---|---|
| 수급/발주 담당자 | 파일 업로드, 오류 수정, 수요·재고 검증, 계산 결과 검토, 보고서·업로드 파일 생성 |

### 3.2 대표 시나리오

1. 사용자가 가상데이터 또는 빈 작업공간으로 새 발주 사이클을 시작한다.
2. 통합 Excel 또는 업무별 Excel 파일을 업로드한다.
3. 시스템이 시트·컬럼·코드·날짜·수량·중복을 검증한다.
4. 사용자가 오류를 수정하거나 화면에서 일부 행을 직접 보정한다.
5. 수요 대시보드에서 OL·SFDC·Trend·Bulk-deal·수급회의 결과를 비교한다.
6. 재고와 Open PO를 확인한다.
7. 기기 발주량과 옵션 발주량을 계산한다.
8. MOQ·Flex·필수 옵션·납기 관련 예외를 검토한다.
9. 사장 보고용 요약 자료를 확인한다.
10. 최종 발주량을 확정하고 System 업로드용 Excel을 다운로드한다.
11. 현재 작업공간을 localStorage에 저장하고 JSON/Excel로 백업한다.

## 4. 제품 원칙

- 대시보드 중심: 전체 진행 상태와 핵심 금액·수량·예외를 첫 화면에서 확인한다.
- Excel 우선: 화면 직접 입력보다 Excel 업로드를 기본으로 한다.
- 계산 근거 공개: 최종 발주량만 보여주지 않고 수요·재고·Open PO·MOQ·Flex 산출 근거를 보여준다.
- 수식과 판단 분리: 반복 계산은 시스템이 수행하고, 수요 확정·예외 승인·수량 조정은 사용자가 결정한다.
- 가상데이터와 실데이터 분리: 데모 데이터가 실제 데이터와 섞이지 않도록 작업공간 유형을 표시한다.
- 원본 보존: 업로드 원본, 업로드 버전, 수정 이력을 보존한다.

## 8. 계산 규칙

### 8.1 수요 확정

기본식:

```text
최종 확정 수요
= 확정 OL
+ 승인된 SFDC/Bulk-deal 조정
+ 수급회의 조정
- 취소·감소 수량
```

확정 상태가 아닌 행은 기본 계산에서 제외한다.

### 8.2 가용재고

```text
가용재고
= 전월말 기말재고
- 예약/할당 재고
- 품질보류 재고
- 출고예정 재고
+ 필요월도 전 확정 입고량
```

### 8.3 기기 발주량

```text
계산 필요량
= 확정 수요
+ 안전재고
- 가용재고
```

```text
최종 발주량
= 계산 필요량을 MOQ·발주단위에 따라 올림한 수량
```

### 8.4 옵션 발주량

```text
기종별 옵션 이론 수요
= 기기 확정 수요 × BOM 수량 × 장착율 × 평균 사용량
```

```text
옵션 계산 필요량
= 기종별 옵션 이론 수요 합계
+ 별도 옵션 수요
+ 안전재고
- 옵션 가용재고
```

필수 옵션은 계산 수요가 0이거나 BOM상 필요한데 수량이 부족하면 경고한다.

### 8.5 MOQ

```text
MOQ 반영 발주량
= ROUNDUP(계산 필요량 / MOQ, 0) × MOQ
```

MOQ로 인해 계산 필요량보다 과도하게 증가하면 `MOQ 과잉 확인` 경고를 표시한다. 실제 발주 확정 여부는 사용자가 판단한다.

### 8.6 Flexibility Rule

초기 MVP에서는 기준정보에 제품 또는 Supplier별 Flex 하한·상한을 입력할 수 있게 한다. 공식 규칙이 없는 경우 기본값은 임시 정책으로 표시하며, 실제 운영 규칙으로 확정된 것으로 간주하지 않는다.

```text
Flex 판정 기준 수량 = 확정 OL 또는 기준 수요
Flex 하한 = 기준 수량 × (1 - 하한 허용률)
Flex 상한 = 기준 수량 × (1 + 상한 허용률)
```

판정 결과:

- 정상
- Flex 미달
- Flex 초과
- 기준 미등록

## 9. 데이터 모델

초기에는 localStorage에 저장하지만, Supabase 전환을 고려해 아래 엔터티를 분리한다.

### 9.1 핵심 엔터티

- `workspaces`: 작업공간, 발주월, 데이터 모드
- `upload_batches`: 업로드 파일, 버전, 검증 상태
- `demand_rows`: 수요 원천 및 확정값
- `inventory_rows`: 기말재고 및 재고 상태
- `open_po_rows`: 미입고 발주
- `item_masters`: 기기·옵션 기준정보
- `bom_rows`: 기종-옵션 연결
- `sales_history_rows`: 과거 실적
- `order_history_rows`: 발주·입고 이력
- `machine_calculations`: 기기 발주 계산 결과
- `option_calculations`: 옵션 발주 계산 결과
- `exceptions`: 예외 및 조정 이력
- `exports`: 생성된 보고서·업로드 파일 메타데이터

### 9.2 모든 주요 데이터에 필요한 공통 필드

- `id`
- `workspace_id`
- `created_at`
- `updated_at`
- `source_type`
- `source_file_id`
- `version`
- `is_active`

## 10. 저장 및 백업

### 10.1 로컬 저장

- 브라우저 localStorage에 작업공간과 현재 데이터를 저장한다.
- 화면 입력·업로드 반영·계산 완료 시 자동 저장한다.
- 저장 실패 시 사용자에게 경고하고 JSON 다운로드를 안내한다.
- 작업공간 초기화 전 확인 모달을 표시한다.

### 10.2 파일 백업

- 전체 작업공간 JSON 내보내기
- 통합 Excel 내보내기
- 사장 보고용 Excel 내보내기
- System 업로드용 Excel 내보내기
- 파일명에 작업공간명과 발주월을 포함한다.

### 10.3 Supabase 전환

Supabase 도입 시 저장 어댑터만 교체할 수 있도록 저장 로직과 화면·계산 로직을 분리한다. MVP에서 사용하는 데이터 구조, 계산 함수, 업로드 검증 함수는 서버 저장 방식과 독립적으로 동작해야 한다.

## 11. 기술 요구사항

### 11.1 로컬 MVP

- React 기반 SPA
- 로컬 개발 서버 실행 가능
- TypeScript 사용
- 컴포넌트와 계산 로직 분리
- 브라우저 localStorage 저장
- Excel 읽기·쓰기 라이브러리 사용
- 반응형 화면
- 주요 화면은 데스크톱 기준 최적화

### 11.2 향후 배포

- 프론트엔드: Vercel
- 데이터베이스·스토리지·인증 확장: Supabase

## 12. 비기능 요구사항

- 초기 화면 로딩은 샘플데이터 기준 3초 이내를 목표로 한다.
- 2,000행 내외의 Excel 업로드를 일반적인 사무용 PC에서 처리한다.
- 계산 결과는 사용자가 재현할 수 있도록 산출 근거를 제공한다.
- 업로드 오류는 행 번호·컬럼명·오류 이유를 표시한다.
- 데이터가 없는 상태에서도 빈 화면이 깨지지 않아야 한다.
- 가상데이터 모드에서는 화면에 `DEMO` 상태를 명확히 표시한다.
- 금액·수량·날짜 형식은 화면과 다운로드 파일에서 일관되게 표시한다.
- 계산 오류·저장 오류·파일 오류는 사용자에게 이해 가능한 메시지로 표시한다.

## 13. 수용 기준

### 13.1 작업공간

- 사용자가 가상데이터 시작과 빈 작업공간 시작 중 하나를 선택할 수 있다.
- 작업공간을 새로 만들고 초기화할 수 있다.
- 새로고침 후에도 localStorage 데이터가 복원된다.

### 13.2 업로드

- 통합 Excel과 업무별 파일을 모두 업로드할 수 있다.
- 오류 행을 반영 전에 확인할 수 있다.
- 정상 데이터만 반영하거나 오류 수정 후 재검증할 수 있다.
- 업로드 파일명·시각·행 수·검증 결과를 확인할 수 있다.

### 13.3 계산

- 수요 확정 여부가 발주 계산에 반영된다.
- Open PO와 재고 상태가 가용재고에 반영된다.
- 기기 발주량과 옵션 발주량이 계산된다.
- MOQ 반영량과 Flex 판정이 표시된다.
- 필수 옵션 누락과 Common품 중복 가능성이 표시된다.
- 사용자가 최종 발주량을 조정하고 사유를 기록할 수 있다.

### 13.4 출력

- 대시보드 금액과 계산 시트 금액이 일치한다.
- 사장 보고용 Excel이 생성된다.
- System 업로드용 Excel에는 확정 행만 포함된다.
- JSON 백업 후 다시 불러오면 작업공간이 복원된다.
